# vpn-link-guard — самая свежая ссылка на VPN-подписку из канала @Happ_VPN_official

Всё решение живёт **только в этом репозитории и на серверах GitHub**:

- **GitHub Actions** раз в час открывает публичную страницу канала `t.me/s/Happ_VPN_official`,
  в самом свежем посте находит секцию **`Incy | v2box | v2raytun`** и забирает
  ссылку на подписку, которая лежит под этим заголовком (ссылка вида
  `https://doroguuuuu.ru/exec?url=...`).
- Ссылка **проверяется живьём**: скачивается её содержимое и считается число
  конфигов («серверов»). Если отдаётся заглушка «Пользователь не найден» —
  это сразу видно на страничке.
- **GitHub Pages** показывает страничку со свежей ссылкой и кнопкой «Скопировать».
- `sub.txt` — живая копия содержимого подписки: можно один раз вписать в клиент
  (Incy / v2box / v2raytun / v2rayNG) и больше никогда не трогать.

Ничего не нужно устанавливать на компьютер или телефон, ничего не нужно покупать,
не нужны Telegram-токены, api_id, Telethon и логин в Telegram. Персональный токен
GitHub тоже не нужен — внутри запуска используется встроенный `GITHUB_TOKEN`,
который GitHub выдаёт сам на время работы.

## Настройка за 5 шагов (около 5 минут)

### 1. Создай репозиторий
GitHub → значок «+» → **New repository** → имя `vpn-link-guard` → видимость **Public**
(публичный репозиторий обязателен: Actions и Pages бесплатны без лимита только там;
ссылки из канала всё равно публичные) → **Create**.

### 2. Залей файлы этого проекта
На странице репозитория: **Add file → Upload files**. Перетащи в окно **содержимое**
распакованной папки: `README.md`, `index.html`, папку `scripts` и папку `.github`
(на macOS папки с точкой скрыты — нажми `Cmd+Shift+.`). Нажми **Commit changes**.

### 3. Впиши канал
**Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**
- Name: `TG_CHANNEL`
- Value: `Happ_VPN_official`

Это единственное, что нужно вписать руками. Опционально можно добавить переменные:
`SUB_MARKER` (по умолчанию уже `Incy | v2box | v2raytun`), `MAX_PAGES` (по умолчанию 3),
`INCLUDE_PATTERN` / `EXCLUDE_PATTERN` (regex-фильтры ссылок).

### 4. Включи GitHub Pages
**Settings → Pages → Source: Deploy from a branch → Branch: main, папка: / (root) → Save.**
Через минуту страница будет по адресу `https://<твой_ник>.github.io/vpn-link-guard/`.

### 5. Первый запуск
**Actions → Update VPN subscription → Run workflow → Run.**
Красным будет, если канал не найден или секция не находится — в логе и в Summary
запуска будет сказано, что поправить. После зелёного запуска `index.html`,
`sub.txt` и `state.json` появятся в репозитории, страничка оживёт.

Дальше всё работает само: проверка каждый час, коммит только при изменениях.

## Где забирать свежую ссылку

**Вариант А — страничка (вручную, всегда актуальна):**
открой `https://<твой_ник>.github.io/vpn-link-guard/` — там ссылка, кнопка
«Скопировать», сколько серверов в подписке прямо сейчас, когда проверено,
история смен ссылок и предупреждение, если автор вдруг отдал недействительную ссылку.

**Вариант Б — прямо в клиенте (один раз, дальше само):**
в Incy / v2box / v2raytun / v2rayNG добавь как подписку (Subscription URL):
```
https://raw.githubusercontent.com/<твой_ник>/vpn-link-guard/main/sub.txt
```
`sub.txt` — это ровно то содержимое, которое отдаёт свежая ссылка автора
(base64-набор конфигов vless), обновляется GitHub'ом после каждой проверки.
Включи в клиенте автообновление подписки.

Если `raw.githubusercontent.com` у твоего провайдера открывается плохо, запасные адреса:
```
https://<твой_ник>.github.io/vpn-link-guard/sub.txt
https://cdn.jsdelivr.net/gh/<твой_ник>/vpn-link-guard@main/sub.txt
```
(jsDelivr кэширует до 12 часов — используй только как запасной.)

## Как выбирается «точно последняя» ссылка

1. Читаются последние посты канала (по умолчанию ~60 сообщений, 3 страницы).
2. Берутся только посты с секцией `Incy | v2box | v2raytun` — объявления и реклама
   без этой секции пропускаются автоматически.
3. Из секции достаются только ссылки **после** заголовка: ключи `crypt…`/`pre`-блоки
   выше секции не трогаются, `tg://proxy` и контакты ботов отфильтровываются.
4. Текущей становится ссылка из **самого свежего** поста с секцией; если ссылка
   встречается впервые (автор обновил закреп или старый пост) — она тоже становится
   текущей.
5. Ссылка скачивается: HTTP 200 + валидные конфиги → живая; HTTP 404 или заглушка
   «Пользователь не найден» → на страничке появится красное предупреждение.
6. `sub.txt` обновляется после каждой проверки, даже если сама ссылка не менялась.

## Честные ограничения

- Cron в GitHub Actions может сдвигаться на несколько минут при высокой нагрузке.
  Автор публикует новый пост раз в час; проверка идёт раз в час, поэтому у тебя
  всегда есть ссылка из последнего опубликованного поста. Хочешь чаще — поменяй
  в `.github/workflows/update.yml` строку `cron: '0 * * * *'` на `'*/30 * * * *'`.
- GitHub отключает расписания после 60 дней без коммитов. В workflow уже встроен
  keepalive (раз в ~50 дней пустой коммит), это лечится само.
- Если автор канала перестанет публиковать ссылки — никакой парсер не поможет,
  смотри дату поста на страничке.

| Файл | Назначение |
|---|---|
| `.github/workflows/update.yml` | расписание (каждый час) + кнопка ручного запуска |
| `scripts/fetch_latest.py` | весь парсинг, проверка и публикация |

## Если что-то не так

- **Красный запуск с 403 при push** — Settings → Actions → General → Workflow permissions
  → «Read and write permissions» → Save (после этого перезапусти workflow).
- **«Канал не найден»** — переменная `TG_CHANNEL` пустая/с опечаткой.
- **«Секция не найдена»** — автор изменил формат поста. Поменяй переменную
  `SUB_MARKER` на актуальный заголовок секции или пришли мне текст поста — поправлю.
- **Партнёрские/рекламные ссылки попадают в кандидаты** — добавь домен в
  `EXCLUDE_PATTERN`, например `.*\/go\/.*|ads\.example\.com`.
